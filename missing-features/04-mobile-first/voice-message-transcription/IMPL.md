## 3. Phase Tasks

### P0 - FFI Foundation
1. Pin whisper.cpp to a stable tag, vendor as submodule.
2. Build prebuilt static libs for iOS arm64 + simulator + Android arm64-v8a/x86_64.
3. Write `whisper_glue.c` with a small JSON-friendly API (`init`, `transcribe_chunk`, `release`).
4. Generate Dart bindings via `ffigen`.
5. Run inference in `Isolate.spawn` worker; communicate via `SendPort`.
6. CapabilityProbe checks RAM, CPU arch, battery, model presence.

### P1 - UI Wiring
7. `TranscriptionOrchestrator` Riverpod service with FIFO+priority queue.
8. Voice bubble shows shimmer until first word lands.
9. Stream segments as they arrive; render with progressive opacity fade-in.
10. Hive cache write on completion.

### P2 - Backend
11. Migration 145.
12. `POST /api/v1/transcribe` multipart handler with size, type, hash, rate-limit checks.
13. In-process worker pool with cgo wrapper around whisper.cpp.
14. `GET /api/v1/transcribe/:id` polling endpoint.
15. Audio sox-resample to 16k mono in memory only.

### P3 - Search Integration
16. `POST /api/v1/messages/:id/transcript` to attach transcript at message-author level.
17. FTS trigger ensures `messages.fts` re-evaluated on transcript change.
18. Search UI surfaces voice-note hits with duration chip.
19. Sender pre-transcription path: when user records, run on-device, attach to message envelope before send.

### P4 - Playback Sync
20. `SyncHighlightController` listens to `audioplayers` position stream, finds matching segment by binary search.
21. Tap-on-word seeks audio (`audioPlayer.seek(Duration(milliseconds: segment.startMs))`).
22. Auto-scroll suppressed on user scroll for 2 s.
23. Accessibility: voice-over announces sender + duration + transcript.

### P5 - Models
24. Download flow for `ggml-base.q5_1` with WiFi-only constraint, resumable download.
25. Validate SHA-256 on load.
26. Battery-aware engine selector.

### P6 - Polish
27. Settings screen with engine selector and download.
28. Telemetry events.
29. Eval harness against LibriSpeech (English) and Common Voice (multi).
30. Feature flag `voice_transcripts_enabled`.

## 5. Rollout

1. Internal dogfood: 5 days.
2. Closed beta: 7 days, 500 users.
3. Open beta: 14 days. Watch p95 latency, fallback rate, crash-free.
4. GA gated by `voice_transcripts_enabled` flag. Kill switch flips orchestrator to "playback only".

## 6. $0 Cost Justification

- Whisper.cpp: MIT license, OSS, free.
- Prebuilt model weights: MIT-permissive, distributed via existing CDN.
- Backend worker uses CPU only; whisper.cpp `tiny.en` decodes 14 s in ~2 s on a single core. Existing API pods have spare CPU; no new infra.
- No third-party services. Cost: $0.

## 7. Risks & Mitigations

| Risk                                          | Mitigation                                                  |
|-----------------------------------------------|-------------------------------------------------------------|
| App size growth from bundled model            | Ship only `tiny.en` (~75 MB); download `base` lazily        |
| FFI crashes on edge devices                   | Crash-safe boundary, fallback to server                     |
| Backend CPU saturation                        | Hard cap on workers per node; queue depth metric + alert    |
| WER below target on accents                   | Public eval per quarter; consider `small` model in v2       |
| Privacy regulator scrutiny                    | On-device by default + explicit opt-in copy                 |
| Audio piracy via cached transcripts           | Cache encrypted at rest with the existing message key       |

## 8. Success Criteria

- 96% of voice notes transcribed within 8 s p95.
- WER targets met on standard eval sets.
- Search hits including transcripts up >= 35% week 4.
- Crash-free transcription sessions >= 99.6%.
- Server fallback usage <= 12% steady state.
